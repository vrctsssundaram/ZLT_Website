# Zepto Logic Website — Production Migration Gate

## Status model

The repository root is **staging source**. It must remain noindex/nofollow.

The deployable production package is generated by:

```
python scripts/prepare_production.py /tmp/zeptologic-production
python scripts/production_audit.py /tmp/zeptologic-production
```

CI uploads the successful result as **zeptologic-production-ready**.

## Pre-migration gate

A production migration is approved only when the same commit has:

- Website Release QA: success
- Static integrity / SEO / disclosure: success
- Chromium multi-device suite: success
- Firefox smoke: success
- WebKit smoke: success
- live enquiry CORS for staging and both production origins: success
- production package audit: success
- Pages staging deployment: success

## Production-host expectations

The generated `.htaccess` targets Apache/LiteSpeed-compatible hosting and provides:

- extensionless canonical routes
- 301 normalization from direct `.html` requests
- custom 404
- `X-Content-Type-Options: nosniff`
- strict-origin referrer policy
- camera/microphone/geolocation denial
- same-origin framing
- conservative asset caching

If production is deployed to a host that does not use Apache/LiteSpeed rewrites, equivalent clean-route and header rules must be configured at that host before cutover.

## Cutover sequence

1. Take a backup/snapshot of the current production site and DNS/hosting configuration.
2. Download the `zeptologic-production-ready` artifact from the approved release run.
3. Confirm the artifact commit SHA matches the approved release commit.
4. Upload to a staging directory/subdomain on the production host if available.
5. Verify:
   - `/`
   - `/products/`
   - `/services/`
   - `/applications/`
   - `/research/`
   - `/about/`
   - `/contact/`
   - specialist landing pages
   - 404 behavior
   - enquiry submission
   - mobile navigation/search/experience controls
6. Replace the public document root only after verification.
7. Purge CDN/server cache.
8. Re-test HTTPS, redirects, canonical tags, robots.txt and sitemap.xml.
9. Submit/refresh sitemap in Search Console after the new site is confirmed live.
10. Monitor enquiries, JavaScript errors, Core Web Vitals and 404s during the first production window.

## Rollback

Keep the pre-cutover production snapshot available. If routing, enquiry delivery, rendering or critical content fails after migration, restore the previous production document root immediately and investigate on staging.
