Before reusing or licensing an RTL block, ask whether it is integration-ready.

An IP-quality audit reviews the existing block as an engineering asset: code quality, clock/reset crossings, documentation, synthesis observations and reuse risks.

Use case

Existing customer RTL, research-grade blocks, internal reusable IP, or a block being prepared for wider integration.

Audit dimensions

A design can simulate correctly and still be difficult to reuse.

The audit does not replace project-specific verification or physical sign-off. It identifies front-end quality and integration risks that should be addressed before the block moves further.

Q-01Lint and code-quality debt.Structural issues · coding consistency · maintainability•
Q-02Clock and reset crossing uncertainty.CDC/RDC review · assumptions · exception quality•
Q-03Integration documentation is incomplete.Interfaces · clocks · resets · parameters · constraints•
Q-04The block is hard to qualify as reusable IP.Readiness gaps · synthesis observations · recommended actions•
Output

An actionable readiness report.

The goal is to separate issues that block reuse from improvements that can wait, so the next engineering decision is clearer.
